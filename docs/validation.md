# نتائج التحقق — 2026-10-15

## البيئة

Linux Debian 13 x64، ذاكرة متاحة نحو 32 GB، Node.js 24.19.0 وnpm 11.9.0. SDK 10.0.402 وruntime/ASP.NET Core 10.0.13، تنزيل رسمي مع SHA512 مطابق لبيانات Microsoft. SQL Server لدى المستخدم على جهازه، ولا توجد وصلة أو إعدادات اتصال في البيئة السحابية. لم تُنشأ أو تُعدل قاعدة عميل.

## النتائج الحالية

| الفحص | النتيجة | الحد العملي |
|---|---|---|
| cloud-setup.sh: tool restore، locked restore، بناء الخادم والواجهة | ناجح، صفر أخطاء وتحذيرات في بناء .NET | أُعيد تشغيل سكربت الإعداد على النسخة الحالية؛ لم تختبر استعادة مهمة سحابية جديدة |
| xUnit API/infrastructure | 22 ناجحة، صفر فاشلة أو متخطاة | SQLite اختبار معزول، ليست SQL Server |
| Vitest/Testing Library | 7 ناجحة، صفر فاشلة | اختبارات مكونات وعميل API، تشمل استجابة الإعداد الفارغة |
| Chromium end-to-end | 7 فحوص ناجحة، صفر أخطاء JavaScript | بيانات اصطناعية عبر Kestrel وSQLite؛ 1440×1000 و390×844 |
| EF migration + idempotent SQL generation | ناجح؛ لا تغييرات نموذج معلقة | توليد فقط، لم ينفذ المخطط على SQL Server |
| Release publish | ناجح | حزمة Linux محايدة للمنصة؛ تشغيل IIS/Windows لم يختبر |
| NuGet advisories لجميع المشاريع وnpm audit | لا ثغرات معلنة في المصادر الحالية | نتيجة وقت الفحص وليست مراجعة أمن شاملة |

الخادم: مصادقة وCookies وCSRF، صلاحيات ونطاق موظف ومدير، فصل المالية، تكرار الرقم والاستيراد، تعديل بنسخة قديمة، دورة مدير، حماية المرفقات وتوقيع النوع، عدم الحفظ الجزئي عند أخطاء الاستيراد، آخر مدير نظام، تفرد ربط الحساب، تغيير دور وتعطيل وكلمة مرور وإبطال الجلسات، قفل الحساب وحد المحاولات، وسجل تدقيق دون قيم مالية أو كلمات مرور.

المتصفح: دخول فعلي، حفظ منشأة، إنشاء موظف وبحث على الخادم، وجوده بعد إعادة التحميل، تخطيط عربي RTL بلا تمدد أفقي للصفحة على الهاتف، كاش PWA يحتوي /offline.html فقط، وظهور السجل الشخصي دون سجلات الآخرين أو تنقل الإدارة للموظف.

الآثار المحلية (مستبعدة من Git): tests/HR.Tests/TestResults/phase1.trx، .local/browser/results.json، employees-desktop.png وemployees-mobile.png، و.local/publish. لا تتضمن بيانات حقيقية.

تم تشخيص وإصلاح مشكلتين كشفهما المتصفح: الاستجابة الخالية عند عدم إعداد المنشأة كانت تبقي حالة التحميل، وربط تسميات بعض select كان غير واضح للمتصفح. الاختبارات النهائية ناجحة بعد الإصلاح. اختبار التحديث عُدّل ليغيّر بيانات فعلية قبل فحص رفض النسخة القديمة.

### متابعة التشغيل على Windows

أرسل المستخدم نتيجة تشغيل Windows: نجحت الاختبارات الوظيفية الـ21، ثم فشلت مرحلة تنظيف fixture بخطأ IOException على tests.db. عُطّل pooling لقاعدة SQLite المؤقتة فقط لتحرير مقابض الملفات، وأضيف اختبار انحدار للإغلاق والحذف (أصبح العدد 22). نجح التشغيل بعد التصحيح على Linux؛ أكد المستخدم لاحقًا نجاح التشغيل بعد التحديث على Windows: 22 ناجحة، صفر فاشلة أو متخطاة، وBuild succeeded. ثم أكد نجاح اختبارات React السبعة وبناء الواجهة ونسخ ملفاتها. ضُبط Cache-Control وPragma معًا بقيم منع التخزين المطلوبة من antiforgery لإزالة تحذير إعادة ضبطها، مع إبقاء الحماية ومنع الكاش.

## غير منفذ / مطلوب

- اتصال وترحيل وتدفق قبول على SQL Server 2022 لدى المستخدم، ثم نسخ واستعادة فعلية إلى قاعدة اختبار جديدة.
- تشغيل التطبيق الفعلي مع SQL على Windows/IIS، شهادة SQL/HTTPS وحسابات خدمة ومفاتيح إنتاج، ومراجعة أمن مستقلة. اختبارات Windows المعزولة وبناء الواجهة نجحت وفق نتيجة المستخدم.
- ترجمة إنجليزية كاملة؛ الموجود تأسيس وقاموس تنقل فقط.
- بقية متطلبات الحضور والإجازات والموافقات والرواتب والأجهزة واختبارات التحميل. لا ادعاء سعة مثبتة لـ1,000 موظف أو تكامل جهاز أو امتثال سعودي أو جاهزية للبيع.

المرجع الرسمي للإصدارات: https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json. إصدارات وحالة الحزم المستقرة والتحقق من Node engine أُخذت من NuGet وregistry.npmjs.org قبل التثبيت، ثم ثُبتت في ملفات القفل.

محاولة SQL migration على Windows وصلت إلى الخادم ثم فشلت في التحقق من الثقة بالشهادة قبل إنشاء القاعدة. لا شهادة معينة صراحة في إعداد الخدمة (Certificate فارغ وForceEncryption=0). أعدت أداة تجهيز شهادة محلية وتعليمات ربط وإعادة تشغيل للمراجعة، دون تطبيقها على جهاز المستخدم. راجع local-sql-certificate.md.
