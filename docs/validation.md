# نتائج التحقق — 2026-10-15

## البيئة

Linux Debian 13 x64، ذاكرة متاحة نحو 32 GB، Node.js 24.19.0 وnpm 11.9.0. SDK 10.0.402 وruntime/ASP.NET Core 10.0.13، تنزيل رسمي مع SHA512 مطابق لبيانات Microsoft. SQL Server لدى المستخدم على جهازه، ولا توجد وصلة أو إعدادات اتصال في البيئة السحابية. لم تتصل البيئة السحابية بقاعدة العميل أو تعدلها؛ نفّذ المستخدم الإعداد محليًا وفق المتابعة أدناه.

## النتائج الحالية

الخادم: مصادقة وCookies وCSRF، صلاحيات ونطاق موظف ومدير، فصل المالية، تكرار الرقم والاستيراد، تعديل بنسخة قديمة، دورة مدير، حماية المرفقات وتوقيع النوع، عدم الحفظ الجزئي عند أخطاء الاستيراد، آخر مدير نظام، تفرد ربط الحساب، تغيير دور وتعطيل وكلمة مرور وإبطال الجلسات، قفل الحساب وحد المحاولات، وسجل تدقيق دون قيم مالية أو كلمات مرور.

المتصفح: دخول فعلي، حفظ منشأة، إنشاء موظف وبحث على الخادم، وجوده بعد إعادة التحميل، تخطيط عربي RTL بلا تمدد أفقي للصفحة على الهاتف، كاش PWA يحتوي /offline.html فقط، وظهور السجل الشخصي دون سجلات الآخرين أو تنقل الإدارة للموظف.

الآثار المحلية (مستبعدة من Git): .local/dashboard-tests.log، .local/browser/results.json، employees-desktop.png وemployees-mobile.png، و.local/publish. لا تتضمن بيانات حقيقية.

تم تشخيص وإصلاح مشكلتين كشفهما المتصفح: الاستجابة الخالية عند عدم إعداد المنشأة كانت تبقي حالة التحميل، وربط تسميات بعض select كان غير واضح للمتصفح. الاختبارات النهائية ناجحة بعد الإصلاح. اختبار التحديث عُدّل ليغيّر بيانات فعلية قبل فحص رفض النسخة القديمة.

### متابعة التشغيل على Windows

أرسل المستخدم نتيجة تشغيل Windows: نجحت الاختبارات الوظيفية الـ21، ثم فشلت مرحلة تنظيف fixture بخطأ IOException على tests.db. عُطّل pooling لقاعدة SQLite المؤقتة فقط لتحرير مقابض الملفات، وأضيف اختبار انحدار للإغلاق والحذف (أصبح العدد 22). نجح التشغيل بعد التصحيح على Linux؛ أكد المستخدم لاحقًا نجاح التشغيل بعد التحديث على Windows: 22 ناجحة، صفر فاشلة أو متخطاة، وBuild succeeded. ثم أكد نجاح اختبارات React السبعة وبناء الواجهة ونسخ ملفاتها. ضُبط Cache-Control وPragma معًا بقيم منع التخزين المطلوبة من antiforgery لإزالة تحذير إعادة ضبطها، مع إبقاء الحماية ومنع الكاش.

## غير منفذ / مطلوب

- استكمال تدفق القبول الكامل على SQL Server 2022 لدى المستخدم، ثم نسخ واستعادة فعلية إلى قاعدة اختبار جديدة. أكد المستخدم نجاح الترحيل وتسجيل الدخول محليًا؛ لم نشاهد بقية التدفقات أو النسخ والاستعادة.
- تشغيل التطبيق الفعلي مع SQL على Windows/IIS، شهادة SQL/HTTPS وحسابات خدمة ومفاتيح إنتاج، ومراجعة أمن مستقلة. اختبارات Windows المعزولة وبناء الواجهة نجحت وفق نتيجة المستخدم.
- ترجمة إنجليزية كاملة؛ الموجود تأسيس وقاموس تنقل فقط.
- بقية متطلبات الحضور والإجازات والموافقات والرواتب والأجهزة واختبارات التحميل. لا ادعاء سعة مثبتة لـ1,000 موظف أو تكامل جهاز أو امتثال سعودي أو جاهزية للبيع.

المرجع الرسمي للإصدارات: https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json. إصدارات وحالة الحزم المستقرة والتحقق من Node engine أُخذت من NuGet وregistry.npmjs.org قبل التثبيت، ثم ثُبتت في ملفات القفل.

## متابعة SQL المحلية

توقفت المحاولة الأولى على Windows بسبب شهادة SQL غير الموثوقة. وافق المستخدم على تجهيز شهادة تطوير موثوقة محليًا وربطها وإعادة تشغيل SQL. عولج فحص CSP في الأداة، ثم أرسل المستخدم مخرجات نجاح إنشاء الشهادة وتجهيز الصلاحيات والثقة. تبع ذلك تأكيد منه لنجاح الترحيل وتسجيل الدخول. بقي التحقق من التدفقات الكاملة والنسخ والاستعادة محليًا، ولا توجد وصلة SQL من السحابة. إعداد الاتصال ما زال Encrypt=True وTrustServerCertificate=False.

- 30 اختبار خادم: أضيفت 8 حالات للوحة المتابعة تشمل الأدوار الأربعة ونطاقها، منع الكشف لحساب Payroll، المصادقة، بداية الشهر حسب يوم الرياض واستبعاد الالتحاق المستقبلي، وفلاتر الدليل وأسماء الهيكل وصلاحية المرفقات. سجل التدقيق يعرض اسم الحساب للمخولين فقط. اختبارات API السابقة لا تزال ناجحة.
- 12 اختبار واجهة: تتضمن 5 حالات جديدة للروابط الداخلية، رفض فقدان التعديلات، الاحتفاظ بالنموذج عند خطأ الخادم، إرسال فلاتر حقيقية، منع صفحة إدارة برابط مباشر وإغلاق قائمة الجوال بعد التنقل. بعض هذه النقاط تتشارك حالة اختبار واحدة.
- 9 فحوص متصفح فعلية: حفظ منشأة وموظف وتحديث عدد اللوحة، الفلاتر ومسحها، بقاء ملف الموظف بعد إعادة التحميل، تأكيد الإغلاق دون حفظ، عرض الجوال والقائمة، الملف الذاتي والمرفقات المسموحة، رفض صفحة الإدارة للموظف، وكاش offline.html فقط. لا أخطاء JavaScript أو مخالفات CSP مرصودة. عولج بقاء القائمة مفتوحة عند تبديل الحساب على الجوال.
- فُحص الوصول إلى حقول الوظيفة والتاريخ بالتمرير داخل ملف الجوال، دون تمدد أفقي للصفحة أو النافذة.
- 6 فحوص لأداة تحديث ZIP باستخدام PowerShell SDK 7.6.7 على Linux وملفات مؤقتة: المعاينة لا تغيّر النسخة، رفض SHA256 غير المطابق، رفض المسارات الخارجة، حفظ الشيفرة القديمة واستثناء الإعدادات والأسرار والملفات الخاصة، رفض الحزمة الناقصة، ورفض نسخة Git. تحليل الصياغة ناجح. لا يثبت ذلك تشغيل فرع -Build عبر Windows PowerShell 5.1؛ هذا الفرع مطلوب التحقق على جهاز المستخدم، وتستعمل أوامره نفس سلسلة البناء التي نجحت لديه سابقًا.
- فحص EF لا يظهر تغييرات نموذج معلقة؛ لا ترحيل جديد في التحديث. نشر Release نجح. لا اعتماد تشغيل جديد ولا خدمة مدفوعة أو خط خارجي.

الصور والنتائج الأصلية في .local/browser (مستبعدة من Git)، وصور مختارة ببيانات اصطناعية في docs/screenshots للمراجعة. لم ينفذ هذا التحديث على جهاز المستخدم من السحابة.

### تصحيح أداة التحديث على Windows PowerShell

أرسل المستخدم فشل التحديث عند السطر الذي يستدعي Assembly.Load باسم System.IO.Compression.FileSystem المختصر. وقع الخطأ بعد التحقق من الأرشيف وقبل مرحلة النسخ والنسخ الاحتياطي؛ لم يطبق تحديث الشيفرة. الاختبارات السابقة على PowerShell SDK/Linux لم تكشف اختلاف حل أسماء المكتبات في Windows PowerShell 5.1.

استُبدل الاستدعاء بـ`Add-Type -AssemblyName System.IO.Compression.FileSystem -ErrorAction Stop` في الأداة وفحوصها، وهو أسلوب PowerShell المدعوم لتحميل المكتبة. أعيدت فحوص حماية الملفات الستة ونجحت على Linux. فُحصت مراجع Microsoft.NETFramework.ReferenceAssemblies.net48 1.0.3 من خلال استعادة NuGet، وأكدت توافر ZipFile.OpenRead وZipArchiveEntry.ExternalAttributes في .NET Framework 4.8. لم ينفذ التشغيل المصحح على Windows في السحابة؛ إعادة تشغيله محليًا لدى المستخدم هي خطوة التحقق المتبقية. لم تتغير فحوص SHA256 أو استثناءات الملفات الخاصة أو أوامر قاعدة البيانات.

مرجع Add-Type الرسمي لـWindows PowerShell 5.1: https://github.com/MicrosoftDocs/PowerShell-Docs/blob/main/reference/5.1/Microsoft.PowerShell.Utility/Add-Type.md.
