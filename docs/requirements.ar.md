أنت مهندس برمجيات أول، ومحلل نظم، ومصمم تجربة مستخدم، ومتخصص في أنظمة الموارد البشرية.

مهمتك بناء منتج فعلي للحضور والانصراف والإجازات والرواتب وطلبات الموظفين، مع بوابة موظف قابلة للتثبيت PWA. المشروع مخصص للسوق السعودي وقابل للبيع والتثبيت لدى العملاء.

أريد تنفيذًا فعليًا بالكود والشاشات وقاعدة البيانات والاختبارات، وليس نموذج واجهات أو خطة فقط.

## 1. سياق المشروع والقيود

- البداية: 100 موظف.
- هدف التوسع: 1,000 موظف، مع إثبات الأداء باختبارات تحميل.
- قاعدة البيانات الموجودة: SQL Server 2022 Enterprise،
  الإصدار 16.0.1000.6.
- لا تفترض أن إعدادات الاتصال متوفرة؛ افحص البيئة ثم اطلب فقط البيانات الناقصة.
- لا تعدّل قواعد بيانات موجودة أو بيانات مشاريع أخرى.
- أنشئ قاعدة بيانات مستقلة لهذا المشروع بعد التأكد من اسمها واتصالها.
- التشغيل الأول على Windows وسيرفر محلي، مع قابلية النشر لدى العميل.
- لا تعتمد على استضافة أو API أو خدمات مدفوعة.
- اختر مكتبات تسمح بالاستخدام التجاري، وسجّل تراخيصها.
- لا تضف ميزات ذكاء اصطناعي أو خدمات خارجية لا يحتاجها النظام.
- الاسم مؤقتًا: HR Platform، واجعله قابلًا للتغيير مركزيًا.
- الواجهة عربية RTL، مع تأسيس الترجمة الإنجليزية.
- واجهة سهلة لمستخدم غير تقني، ومتجاوبة للجوال.

## 2. التقنيات والبنية

اعتمد:
- ASP.NET Core على .NET 10 LTS.
- EF Core مع SQL Server.
- React + TypeScript + Vite.
- PWA لبوابة الموظف.
- ASP.NET Core Identity لإدارة الحسابات.
- اختبارات مناسبة للخادم والواجهة والتكامل.

تحقق من الإصدارات المستقرة المدعومة والتوافق قبل تثبيت الحزم.

استخدم Modular Monolith:
تطبيق موحد مقسم إلى وحدات واضحة، دون Microservices أو تعقيد غير ضروري.

افصل:
- قواعد العمل.
- حالات الاستخدام.
- الوصول للبيانات والتكاملات.
- API.
- الواجهة.

اجعل النشر الأول قاعدة بيانات مستقلة لكل عميل.
ادعم الفروع والأقسام داخل العميل، ولا تنفذ منصة SaaS متعددة العملاء الآن.
لا تفترض أن فصل الفروع يكفي لعزل عملاء مستقلين.

## 3. الوحدات المطلوبة

أ. التأسيس:
- إعداد المنشأة والفروع والأقسام والوظائف.
- المستخدمون والأدوار والصلاحيات ونطاق الوصول.
- ربط حساب الموظف بملفه.
- المدير المباشر.
- سجل تدقيق للتغييرات الحساسة.
- إعدادات النظام وسياسات المنشأة.

ب. الموظفون:
- البيانات الأساسية والوظيفية.
- تاريخ الالتحاق والحالة الوظيفية والعقد.
- بيانات الراتب والبنك وIBAN بصلاحيات خاصة.
- مرفقات محفوظة خارج المجلد العام.
- استيراد الموظفين من Excel بقالب واضح ومعاينة الأخطاء قبل الحفظ.
- منع تكرار الرقم الوظيفي.

ج. الحضور:
- جداول العمل والشفتات الثابتة والمتغيرة.
- شفتات تعبر منتصف الليل.
- الراحة الأسبوعية والعطلات والاستراحات وفترات السماح.
- سجل حركات خام غير قابل للتعديل المباشر.
- نتائج حضور مشتقة يمكن إعادة احتسابها وفق صلاحيات وسياسات واضحة.
- التأخير والانصراف المبكر والغياب ونقص البصمات.
- الإضافي المطلوب والمعتمد منفصل عن مجرد بقاء الموظف بعد الدوام.
- تصحيح الحضور بموافقة، مع حفظ الأصل وسجل التغيير.
- منع تكرار الحركات وتعارض الطلبات.
- الحضور من البوابة حسب سياسة المنشأة.
- عند استخدام الموقع: التحقق على الخادم قدر الممكن، وحفظ دقة الموقع،
  وعدم وصف GPS وحده بأنه يمنع التلاعب.
- لا تعتمد على ساعة جهاز الموظف باعتبارها المصدر المعتمد للوقت.

د. الإجازات:
- أنواع وسياسات قابلة للإعداد بتاريخ سريان.
- الاستحقاق والتراكم والترحيل والانتهاء والأرصدة الافتتاحية.
- سجل حركات رصيد يمكن تتبعه.
- الطلب والمرفقات والموافقات والرفض والسحب والإلغاء.
- منع التداخل وحجز الرصيد أثناء الطلب وفق السياسة.
- إعادة الرصيد عند الإلغاء وفق حالة الطلب.
- الربط بالحضور والرواتب.
- استيراد الأرصدة مع التحقق وسجل العملية.

هـ. الطلبات:
- إذن.
- تصحيح حضور.
- إجازة.
- سلفة.
- تعريف بالراتب.
- طلب عام.
- طلب تغطية: مبادرة من الموظف لتغطية زميله.
- تكليف: يصدر من الإدارة، مستقل عن طلب التغطية ولا يشترط تغطية زميل.
- مسارات موافقة قابلة للإعداد، وتفويض معتمد.
- منع اعتماد المستخدم طلبه الشخصي.
- سجل حالة وملاحظات ومرفقات وإشعارات داخلية.

و. الرواتب:
- الأساسي والبدلات والمكافآت والمتغيرات بتاريخ سريان.
- الإضافي والغياب والإجازات غير المدفوعة والسلف والاستقطاعات.
- التأمينات حسب فئة الموظف والقواعد السارية التي يتم التحقق منها.
- فروقات وتسويات بأثر واضح.
- دورة مسير: مسودة، احتساب، مراجعة، اعتماد، إقفال.
- حفظ تفاصيل المدخلات والمعادلات والسياسات المستخدمة لكل مسير.
- التغييرات اللاحقة لا تغير مسيرًا مقفلًا.
- إعادة الفتح بصلاحية خاصة وسجل تدقيق، أو معالجة الفرق في مسير لاحق.
- كشف راتب للموظف، وتقارير وتصدير.
- لا تعتبر تصدير Excel تكاملًا مع حماية الأجور أو البنوك.
- أي ملف بنكي أو حماية أجور يحتاج مواصفة رسمية واختبارًا مستقلًا.
- استخدم decimal للقيم المالية، وحدد قواعد التقريب صراحة.

ز. البوابات:
بوابة الموظف:
- الرئيسية، حضوري، طلباتي، إجازاتي، كشوف راتبي، ملفي، التنبيهات.

بوابة المدير:
- الفريق، استثناءات الحضور، الطلبات المعلقة والموافقات.

الإدارة:
- لوحة متابعة عملية، الموظفون، الحضور، الإجازات، الطلبات،
  الرواتب، الأجهزة، التقارير، الإعدادات.

لا تعرض للمستخدم ما لا تسمح به صلاحياته.
فرض الصلاحيات في الخادم إلزامي، وليس إخفاء الأزرار فقط.

## 4. التكامل مع ZKTeco

لا يوجد موديل محدد أو جهاز متاح حاليًا.

- صمم واجهة موحدة لموصلات الأجهزة.
- افصل الموصل عن حسابات الحضور.
- جهز سجل الأجهزة وربط أرقامها بالموظفين.
- جهز المزامنة، وإعادة المحاولة، ونقاط الاستكمال،
  ومنع التكرار، ومعالجة انقطاع الاتصال.
- استخدم محاكيًا واضح التسمية لاختبار التدفق.
- أضف استيراد حركات من ملف كبديل أولي.
- لا تدّعِ وجود تكامل فعلي قبل اختباره على جهاز متوافق.
- لا تفترض دعم PUSH أو SDK أو بروتوكول واحد لكل الأجهزة.
- لا تستخدم SDK مجهول الترخيص أو تعد بأنه مجاني قبل التحقق.
- لا تجمع قوالب بصمات بيومترية؛ المطلوب أولًا حركات الحضور فقط.

## 5. المتطلبات السعودية

قبل تنفيذ القواعد النظامية:
- راجع المصادر الرسمية الحالية لوزارة الموارد البشرية والتأمينات
  والجهات المختصة بحسب الميزة.
- أنشئ docs/saudi-rules.md يتضمن المصدر وتاريخ التحقق
  والقواعد التي ستؤثر في الحسابات.
- افصل المتطلبات النظامية عن سياسة المنشأة.
- اجعل القواعد والنسب وتواريخ سريانها قابلة للتحديث.
- لا تخترع نسبًا أو مددًا أو تدّعي امتثالًا كاملًا دون تحقق.
- إذا تعذر الوصول للمصدر، اذكر القاعدة غير المتحققة
  ولا تستخدمها بصمت في الرواتب الإنتاجية.

## 6. الأمان والبيانات

- استخدم مصادقة آمنة مناسبة للويب وPWA،
  وفضّل Cookies آمنة HttpOnly عند خدمة الواجهة وAPI من نفس النطاق،
  مع حماية CSRF المناسبة.
- لا تحفظ رموز دخول طويلة العمر في localStorage.
- لا تضع أسرارًا في الكود أو Git أو السجلات.
- استخدم User Secrets أو متغيرات البيئة محليًا.
- تحقق من ملكية السجلات في كل طلب API.
- حماية رفع وتنزيل المرفقات والتحقق من النوع والحجم.
- منع التخمين المتكرر للدخول، وإدارة الجلسات.
- حماية بيانات الراتب والهوية والموقع حسب الصلاحيات.
- PWA لا تخزن كشوف الرواتب أو بيانات الموظفين الحساسة في Cache عام.
- تسجيل الحضور النهائي يتطلب تأكيد الخادم؛
  لا تعرض نجاحًا نهائيًا لعملية لم تُحفظ.
- أضف نسخًا احتياطيًا واستعادة موثقة، واختبر الاستعادة.
- لا تفتح منفذ SQL Server مباشرة للإنترنت.
- خزن التواريخ والأوقات بطريقة موحدة، مع منطقة زمنية للمنشأة
  ويوم عمل محلي صحيح للشفتات الليلية.

  وحركات ممتدة ودفعة حضور متزامنة.

## 8. طريقة العمل

أولًا:
1. افحص المجلد والبيئة والأدوات المتاحة.
2. لا تلمس أي مشروع أو قاعدة موجودة.
3. أنشئ:
   - AGENTS.md: قواعد المشروع.
   - docs/scope.md: النطاق والافتراضات.
   - docs/architecture.md: البنية وقراراتها.
   - docs/data-model.md: الكيانات والعلاقات الأساسية.
   - docs/roadmap.md: مراحل التنفيذ ومعايير قبولها.
   - docs/progress.md: ما أنجز وما بقي والعوائق.
4. لا تتوقف عند الوثائق؛ ابدأ بعدها التنفيذ الفعلي ضمن نفس المهمة.

ترتيب التنفيذ:
1. التأسيس والمصادقة والصلاحيات والهيكل والموظفون.
2. الحضور والجداول واستيراد الحركات.
3. الإجازات والطلبات والموافقات وبوابة الموظف.
4. الرواتب وكشوفها.
5. موصلات الأجهزة والتحسينات واختبارات التحميل والنشر.

تقدم على مراحل مكتملة وقابلة للتشغيل، دون نسيان النطاق الكامل.
لا تطلب مني تجربة كل زر بدل إجراء اختباراتك.
اسأل فقط عندما تكون معلومة ناقصة تمنع التنفيذ الصحيح،
مثل اسم سيرفر SQL وطريقة المصادقة.
استمر في الأعمال المستقلة أثناء انتظار الإجابة.

## 9. الاختبارات والتسليم

اختبر خصوصًا:
- الشفت الليلي وغياب بصمة.
- تكرار استيراد نفس الحركات.
- تعارض إجازتين.
- اعتمادين متزامنين وتأثيرهما على الرصيد.
- منع الموظف من قراءة راتب أو طلب موظف آخر.
- تغير الراتب أو السياسة خلال فترة الحساب.
- عدم تغير مسير مقفل بعد تعديل الحضور.
- إلغاء طلب معتمد وأثره على الرصيد والحضور.
- تدفق: طلب إجازة، اعتماد، تحديث رصيد وحضور، ثم احتساب راتب.

سلّم:
- كود حقيقي وMigrations.
- تعليمات إعداد وتشغيل واضحة على Windows.
- بيانات تجريبية منفصلة عن الإنتاج.
- إعداد اتصال مثال بلا أسرار.
- نتائج الاختبارات وما لم يتم اختباره.
- خطوات النشر والنسخ الاحتياطي والاستعادة.
- قائمة بالتراخيص والتكاملات غير المكتملة.

لا تستخدم صفحات وهمية أو بيانات ثابتة باعتبارها وظائف منجزة.
لا تصف المشروع بأنه جاهز للبيع إلا بعد تحقق معايير القبول،
ومراجعة الأمان والحسابات والتشغيل.

ابدأ الآن بفحص البيئة وإنشاء أساس المشروع،
ثم نفذ أول مرحلة كاملة واختبرها، وحدّث ملفات التقدم.
