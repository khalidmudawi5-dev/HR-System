# Tests

`dotnet test HRPlatform.sln --no-restore` runs xUnit API/infrastructure tests on SQLite. Each factory creates its own synthetic database and private storage, then removes them. Real SQL Server is not contacted. Per-client IPs are injected by test-only middleware to exercise the production login limiter without making the whole suite one client.

SQLite connection pooling is disabled for these disposable test databases so native handles close when scopes finish. Pooled handles previously caused Windows to reject directory cleanup after all assertions passed. The regression test opens the database file exclusively after scoped access and verifies that disposing the isolated host removes its directory. Other hosts' pools and the production SQL Server configuration are untouched.

`cd web && npm test` runs Vitest/Testing Library UI and request-client tests. These verify command submission, error handling, authorization navigation and import-error gating; they do not replace server authorization tests.

## Browser flow

Build and copy web/dist to src/HR.Api/wwwroot (scripts/build.ps1 on Windows), then:

```powershell
dotnet run --project tests/HR.BrowserHost
```

In another terminal, after installing a compatible Chromium through Playwright (`cd web; npx playwright install chromium`):

```powershell
node scripts/browser-smoke.cjs
```

On the cloud machine a system Chromium is available; set `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium` for that command. BrowserHost is explicitly test-only, exposes synthetic test accounts and must never be published as the application. Stop it after testing. Its data is disposable and does not touch SQL Server. Run the browser flow against a fresh host; its employee number is deliberately fixed so repeated runs detect duplicate persistence.

The flow checks login, real dashboard metrics and their refresh after employee creation, organization save, directory filters/reset, deep profile routes after reload, unsaved-change discard, mobile navigation/profile scrolling, employee isolation and PWA cache. It also checks for JavaScript errors and observed CSP violations. Screenshots/results are generated in .local/browser and excluded from Git. No localhost preview links are published by cloud onboarding.

## ZIP updater file safety

`powershell -NoProfile -File tests/Update-LocalProject.Tests.ps1` uses disposable source files and ZIP archives, never customer databases. It exercises preview, checksum failure, archive traversal rejection, source backup and private/configuration exclusions, incomplete packages and refusal of Git checkouts. It needs no Pester dependency. These checks ran in an isolated PowerShell SDK 7.6.7 host on Linux; the Windows PowerShell 5.1 build command branch remains a local verification step.

Dashboard API fixtures inject a fixed TimeProvider: 30 September at 22:00 UTC is 1 October in Riyadh. The monthly metric includes the current local date and excludes a future joiner. Scope assertions test actual responses for Administrator, HR, Manager, Employee and Payroll; directory filters must never widen that scope.

## Attendance (2026-10-18)

The attendance suite covers cross-midnight work, incomplete/duplicate event sequences, interval-based unpaid breaks, grace and rounding, holiday/rest states, correction overlays, capture boundaries, immutable raw data, scope and denied Payroll access. API tests cover atomic/idempotent Excel imports and formula rejection, roster overlap rejection, stale schedule versions, self/out-of-team review rejection, cancellation releasing a reservation, competing reviewers (one success/one conflict), and portal server time and retry keys. Notes accept line breaks while rejecting other controls.

After a fresh HR.BrowserHost and the foundation smoke test, run `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node scripts/attendance-browser-smoke.cjs`. It uses the XLSX fixture generated by the test host in .local/browser, then exercises actual shift/roster UI, duplicate import, employee correction, direct-manager approval and mobile portal registration. Run both scripts once per fresh host; their mutations are intentionally detectable on repeated runs. The host clock is frozen for deterministic attendance, and all accounts/data are synthetic.

SQLite transaction/concurrency tests do not establish SQL Server locking behavior. The generated additive SQL Server migration is checked offline; applying and accepting it on the user's HRPlatform_Dev remains a separate local verification step.
